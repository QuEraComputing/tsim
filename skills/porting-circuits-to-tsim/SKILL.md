# Porting published circuits to Tsim

Papers about non-Clifford protocols often publish Stim circuits in which every T gate is
replaced by a Clifford stand-in, because Stim cannot simulate T. Tsim can, so the same circuits
can be rerun with real T gates. This skill covers getting the circuits, converting them, checking
the conversion, and deciding what is feasible. It builds on the `simulating-circuits-with-tsim`
skill (active width, sampling) and hands off to `running-qec-experiments-with-tsim` for the
actual statistics.

Copy this checklist and tick items off as you go. Do not report numbers from a converted
circuit until every validation item is ticked; if one cannot pass, say which and why.

```
Porting:
- [ ] 1. Circuit files found; source (URL, commit or DOI) recorded next to them
- [ ] 2. Stand-in convention identified from the paper; conversion confirmed with the user
- [ ] 2. Converted; T count matches the paper (CCZ/CCX count as 7)
- [ ] 3. Stand-in in Tsim (reference flags) agrees with Stim within error bars
- [ ] 3. Noiseless real circuit: no detector used for postselection or decoding fires
- [ ] 3. Noiseless real circuit: every observable is deterministic
- [ ] 3. Noiseless stand-in: observables checked; random ones noted in the report
- [ ] 4. Active width (or the width error) recorded for every circuit
- [ ] 5. Plan reported: what is feasible, and what was modified and why
```

## 1. Find the published circuits

Use the authors' files whenever they exist; regenerating circuits from the paper's description
introduces differences that are hard to find later.

- **arXiv source:** `https://arxiv.org/e-print/<arxiv-id>` downloads the source bundle (usually
  a gzipped tar). Circuits are sometimes attached as `.stim` files, and the `.tex` names data and
  code links that the PDF hides. Treat downloaded archives as untrusted: unpack into an empty
  directory and only read the files.
- **Code and data links:** GitHub, Zenodo and figshare links in the paper, its data
  availability statement, and the authors' GitHub profiles. Circuits are also embedded in
  notebooks or generated by scripts in these repositories.
- **Ask the user** whether they have circuits from the authors before rebuilding anything.

Record where each circuit came from (URL and commit or version) next to the circuit file.

## 2. Load and convert stand-in gates

```python
import tsim

c = tsim.Circuit(
    """
    RX 0
    S 0
    DEPOLARIZE1(0.001) 0
    S_DAG 0
    MX 0
    OBSERVABLE_INCLUDE(0) rec[-1]
    """
)
```

Use `tsim.Circuit.from_file(path)` for files; `tsim.Circuit(...)` also accepts a `stim.Circuit`.
Tsim accepts every Stim instruction.

Read the paper's methods section to find which gates stand in for the non-Clifford ones.
Common conventions:

- `S` and `S_DAG` in place of `T` and `T_DAG` (the most common; the protocol's checks then see
  an S state, which is also a stabilizer state).
- A |Y⟩ = S|+⟩ input in place of a |T⟩ = T|+⟩ input: replace the `S` of the preparation by `T`,
  and check that the final readout measures the T state's stabilizer (step 3).
- Tagged instructions, such as Tsim's own `S[T]` and `S_DAG[T]`, which Tsim already reads as
  `T` and `T_DAG`.
- A `CCZ` or `CS` modelled only by its noise, for example correlated `E(p) Z Z Z ...` errors on
  the qubits it would act on, with the gate itself left out. Insert the real gate at those
  locations; the error targets often identify the qubits.
- A comment, coordinate or `QUBIT_COORDS` marker identifying the magic qubits.

Some proxies cannot be converted by substitution. If every magic state is replaced by a logical
|0⟩ or |+⟩ and the conditional S corrections that a real T gate needs are absent (common in
logical-level and lattice-surgery benchmarks), real T gates need an encoded magic-state
preparation and those corrections. Tell the user rather than patching the circuit.

Replace only the stand-ins: a circuit can also contain ordinary `S` gates that must stay. When
the stand-ins are not marked, find them from the paper (for example, the gates on the injection
qubit and in the check rounds) and confirm the choice with the user.

When every untagged `S` and `S_DAG` is a stand-in, a line-anchored substitution converts them
all. It leaves `S[T]` lines alone, since Tsim already reads those as T:

```python
import re

real_text = re.sub(
    r"^(\s*)S(_DAG)?(?=\s|\[(?!T\]))", r"\1T\2", str(c), flags=re.MULTILINE
)
real = tsim.Circuit(real_text)
assert real.tcount() == 2
```

When only some are stand-ins, change those lines individually (for example, only the `S`
lines that target the injection qubit), and compare `real.tcount()` with the number of T gates
the paper states. `tcount()` counts each `CCZ` or `CCX` as 7.

To vary the noise strength, rebuild the circuits with the authors' generator when there is
one. Rescaling a published file by hand must change every noise argument, including
`PAULI_CHANNEL_2` and measurement flips such as `M(0.001)`; a missed channel shifts results
without any error.

## 3. Validate the conversion

Run these checks before trusting any number from the converted circuit:

1. **Stand-in matches Stim.** Sample the original stand-in circuit in Tsim (with
   `use_detector_reference_sample=True` and `use_observable_reference_sample=True`) and in Stim.
   Detector and observable rates must agree within error bars. If the paper reports numbers for
   the stand-in circuit, reproduce one of them.
2. **Noiseless real circuit.** In `real.without_noise()`, every detector used for postselection
   or decoding must be 0 on every shot, and the output should be the ideal state (for example,
   infidelity 0 with the fidelity measurement of `running-qec-experiments-with-tsim`). A
   detector that fires without noise usually means one of:
   - a stand-in was missed, or a non-stand-in `S` was converted;
   - a Pauli correction is missing. A stand-in circuit can skip feed-forward corrections (for
     example an X-frame correction after a random check) that do not matter for S or a noise
     model, but do once the gate is a real T or CCZ.
3. **Observables of the real circuit.** In `real.without_noise()`, every observable must be
   deterministic. If the circuit ends by measuring the magic state in a Pauli basis (a final
   logical X or Y readout), the observable is random on a T state. Add a noiseless T-basis
   readout instead, as in the fidelity measurement of `running-qec-experiments-with-tsim`, and
   say that you did. Published circuits often need this.
4. **Observables of the stand-in.** Sample the noiseless stand-in and check whether its
   observables are deterministic. Often they are not: a final check written as `S; MPP Y;
   S_DAG` measures the T state's stabilizer once S becomes T, but measures X on the stand-in's
   S state, which is random. Such a stand-in gives only acceptance rates, not logical error
   rates; say so instead of reporting a meaningless error rate. To compare error rates, build a
   stand-in variant whose final check matches the S state (for example, drop the `S`/`S_DAG`
   around `MPP Y`), label it as your modification, and verify it is deterministic without noise.

## 4. Measure the active width (k_max)

Compile without sampling and read the active width, which decides whether the circuit is
feasible (see the `simulating-circuits-with-tsim` skill for the scale). Compiling needs no
sampling, but it is not free: it takes seconds for a few thousand detectors and about a minute
at 50,000.

Above width 30, compiling raises a `ValueError` whose message states the width, so a survey
loop should record the error instead of stopping:

```python
def survey_row(circuit):
    row = [circuit.num_qubits, circuit.tcount(), circuit.num_detectors]
    try:
        sampler = circuit.compile_detector_sampler()
        return row + [sampler.active_width]  # Tsim 1.0.0: see simulating-circuits-with-tsim
    except ValueError as error:
        return row + [str(error)[:120]]  # "needs N active qubits ..."


print(survey_row(real))
```

When surveying several circuits or sizes, report one row per circuit:

| Circuit (source) | Qubits | T count | Detectors | Active width | Shots/s (cores) |
|---|---|---|---|---|---|

Measure shots per second only for circuits whose width makes it quick, with postselection on if
the protocol postselects, and state the number of threads. If a family of circuits is surveyed
by size (distance, rounds), report how the width grows; that is often the main result.

## 5. Plan the study

- Width small enough: run the paper's figure with real T gates using
  `running-qec-experiments-with-tsim`, and plot the stand-in and real results together; the
  difference is usually the point.
- Width too large: say so with the measured width and an estimate of time per shot, suggest
  the largest instance that is feasible, and suggest opening an issue with the full circuit
  (see "Reporting bugs and circuits Tsim cannot simulate yet" in the
  `simulating-circuits-with-tsim` skill).
- Note anything Tsim cannot express. Simulator-specific instructions from other tools (for
  example expectation-value instructions) need a Tsim equivalent such as the fidelity
  measurement in `running-qec-experiments-with-tsim`.

If a published circuit fails to parse or compile in Tsim although Stim accepts it, reduce it to
a small reproducer and report it as described in the `simulating-circuits-with-tsim` skill.
