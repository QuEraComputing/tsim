## class `ChannelSampler`

```python
ChannelSampler(channel_probs: list[np.ndarray], error_transform: np.ndarray, seed: int | None = None)
```

Samples from multiple error channels and transforms to a reduced basis.

This class combines multiple error channels (each producing error bits e0, e1, ...)
and applies a linear transformation over GF(2) to convert samples from the original
"e" basis to a reduced "f" basis using geometric-skip sampling optimized for
low-noise regimes.

``f_i = error_transform_ij * e_j mod 2``. Within each channel,
probability-array bit 0 corresponds to the first produced error bit, bit 1
to the second, and so on.

Channels are automatically simplified by:
1. Removing bits e_i that do not affect any f-variable (i.e. all-zero columns in error_transform)
2. Folding duplicate column IDs, i.e. channels whose column signatures contain duplicate IDs.
3. Merging channels with identical column signatures, i.e. channels whose corresponding
    columns in error_transform are identical.
4. Absorbing channels whose signatures are subsets of others, i.e. channels whose corresponding
    columns in error_transform are a strict subset of another channel's columns.

**Example:**

\>\>\> probs = [error_probs(0.1), error_probs(0.2)]  # two 1-bit channels
\>\>\> transform = np.array([[1, 1]])  # f0 = e0 XOR e1
\>\>\> sampler = ChannelSampler(probs, transform)
\>\>\> samples = sampler.sample(1000)  # shape (1000, 1)

### `sample`

```python
sample(num_samples: int = 1, seeds: np.ndarray | None = None) -> np.ndarray
```

Sample from all error channels and transform to new error basis.

Uses geometric-skip sampling, optimized for low-noise regimes where
P(non-identity) \<\< 1 per channel. Blocks of shots are sampled in
parallel, each from its own random stream, so the samples depend on the
seed and ``num_samples`` but not on the number of threads.

**Parameters:**

- `num_samples` (`int`) — Number of samples to draw.
- `seeds` (`np.ndarray | None`) — The blocks' seeds from ``block_seeds(num_samples)``; drawn here if ``None``.

**Returns:**

- `np.ndarray` — NumPy array of shape (num_samples, num_f) with uint8 values indicating
- `np.ndarray` — which f-variables are set for each sample.

### `word_tables`

```python
word_tables(f_index: np.ndarray, bit: np.ndarray, bits: int = 64) -> WordTables
```

Return the fault outcomes' flips on rows of words of ``bits`` bits.

F-variable ``f_index[j]`` flips bit ``bit[j]`` of a row (bit ``b`` is bit
``b % bits`` of word ``b // bits``), so a row holds the XOR of its set
f-variables' bits. The pairs must be distinct. Rows are of uint64 words
for ``bits=64`` and of a uint8 per bit for ``bits=1``.

### `append`

```python
append(name: str | stim.CircuitInstruction | stim.CircuitRepeatBlock | stim.Circuit, targets: int | stim.GateTarget | stim.PauliString | Iterable[int | stim.GateTarget | stim.PauliString] = (), arg: float | Iterable[float] | None = None, tag: str = '') -> None
```

Append an operation into the circuit.

Besides Stim's gates, this accepts Tsim's gates:

- ``T``, ``T_DAG`` on qubits, and ``TPP``, ``TPP_DAG`` on Pauli products.
- ``R_X``, ``R_Y``, ``R_Z`` and ``U3`` on qubits, ``R_XX``, ``R_YY`` and
  ``R_ZZ`` on two distinct qubits, and ``R_PAULI`` on Pauli products.
  ``U3`` takes three angles ``(theta, phi, lambda)`` as ``arg``, the
  others one. Angles are in units of π.
- ``CCZ`` and ``CCX`` on bare qubit targets, in groups of three. They are
  appended as their Clifford+T decomposition.

The other Tsim gates are stored as tagged Clifford placeholders.

Gate names are case-insensitive.

**Parameters:**

- `name` (`str | stim.CircuitInstruction | stim.CircuitRepeatBlock | stim.Circuit`) — The name of the operation's gate (e.g. "H" or "M" or "CNOT"). This argument can also be set to a `stim.CircuitInstruction`, `stim.CircuitRepeatBlock` or `stim.Circuit`, which results in the instruction, block or circuit being appended to the circuit. The other arguments (targets, arg and tag) can't be specified when doing so.
- `targets` (`int | stim.GateTarget | stim.PauliString | Iterable[int | stim.GateTarget | stim.PauliString]`) — The objects operated on by the gate. This can be either a single target or an iterable of multiple targets. Each target can be: An int: The index of a targeted qubit. A `stim.GateTarget`: Could be a variety of things. Methods like `stim.target_rec`, `stim.target_sweep_bit`, `stim.target_x`, and `stim.CircuitInstruction.__getitem__` all return this type. A `stim.PauliString`: This will automatically be expanded into a product of pauli targets like `X1*Y2*Z3`.
- `arg` (`float | Iterable[float] | None`) — The "parens arguments" for the gate, such as the probability for a noise operation. A double or list of doubles parameterizing the gate. Different gates take different parens arguments. For example, X_ERROR takes a probability, OBSERVABLE_INCLUDE takes an observable index, PAULI_CHANNEL_1 takes three disjoint probabilities, and R_X takes an angle in units of π.
- `tag` (`str`) — A customizable string attached to the instruction.

### `compile_detector_sampler`

```python
compile_detector_sampler(strategy: SamplingStrategy = 'active_statevector', seed: int | None = None) -> CompiledDetectorSampler
```

Compile circuit into a detector sampler.

Connected components whose single output is deterministically given by
one f-variable, or is a constant, are handled via a fast direct path (no
compilation or autoregressive sampling).  Remaining components go
through the full compilation pipeline.

**Parameters:**

- `strategy` (`SamplingStrategy`) — "active_statevector" (the default) to simulate each non-direct component on a dense state vector over its active qubits, or a stabilizer rank decomposition strategy ("cat5", "bss", "cutting"). "active_statevector" samples on the CPU, on ``numba.get_num_threads()`` threads.
- `seed` (`int | None`) — Random seed for the sampler. If None, a random seed is drawn. With "active_statevector", and under any strategy for a circuit without non-direct components, the samples of a seed depend on neither the batch size nor the thread count; with a stabilizer-rank strategy they are only deterministic for a fixed batch size and fixed reference sample settings.

**Returns:**

- `CompiledDetectorSampler` — A CompiledDetectorSampler that can be used to sample detectors and observables.


### `compile_m2d_converter`

```python
compile_m2d_converter(skip_reference_sample: bool = False) -> stim.CompiledMeasurementsToDetectionEventsConverter
```

Create a measurement-to-detection-event converter for the given circuit.

The converter can efficiently compute detection events and observable flips
from raw measurement data.

The converter uses a noiseless reference sample, collected from the circuit
using Stim's Tableau simulator during initialization of the converter, as a
baseline for determining what the expected value of a detector is.

Note that the expected behavior of gauge detectors (detectors that are not
actually deterministic under noiseless execution) can vary depending on the
reference sample. Stim mitigates this by always generating the same reference
sample for a given circuit.

**Parameters:**

- `skip_reference_sample` (`bool`) — Defaults to False. When set to True, the reference sample used by the converter is initialized to all-zeroes instead of being collected from the circuit. This should only be used if it's known that the all-zeroes sample is actually a possible result from the circuit (under noiseless execution).

**Returns:**

- `stim.CompiledMeasurementsToDetectionEventsConverter` — An initialized stim.CompiledMeasurementsToDetectionEventsConverter.

### `detector_error_model`

```python
detector_error_model(decompose_errors: bool = False, flatten_loops: bool = False, allow_gauge_detectors: bool = False, approximate_disjoint_errors: bool | float = False, ignore_decomposition_failures: bool = False, block_decomposition_from_introducing_remnant_edges: bool = False) -> stim.DetectorErrorModel
```

Return a stim.DetectorErrorModel describing the error processes in the circuit.

Unlike the stim.Circuit.detector_error_model() method, this method allows for non-deterministic observables
when `allow_gauge_detectors` is set to true.

**Warning:**

By default (`decompose_errors=False`) the model is not decomposed. Matching decoders such as
PyMatching build their graph only from error mechanisms that flip at most two detectors, and silently
ignore the rest, which can raise the logical error rate substantially. Set `decompose_errors=True`
when the model is meant for a matching decoder.

**Parameters:**

- `decompose_errors` (`bool`) — Defaults to false. When set to true, the error analysis attempts to decompose the components of composite error mechanisms (such as depolarization errors) into simpler errors, and suggest this decomposition via `stim.target_separator()` between the components. For example, in an XZ surface code, single qubit depolarization has a Y error term which can be decomposed into simpler X and Z error terms. Decomposition fails (causing this method to throw) if it's not possible to decompose large errors into simple errors that affect at most two detectors. Decomposition keeps the logical observables as observables, as Stim does, so it requires them to be deterministic: Stim raises a ValueError otherwise.
- `flatten_loops` (`bool`) — Defaults to false. When set to true, the output will not contain any `repeat` blocks. When set to false, the error analysis watches for loops in the circuit reaching a periodic steady state with respect to the detectors being introduced, the error mechanisms that affect them, and the locations of the logical observables. When it identifies such a steady state, it outputs a repeat block. This is massively more efficient than flattening for circuits that contain loops, but creates a more complex output. Irrelevant unless allow_gauge_detectors=False.
- `allow_gauge_detectors` (`bool`) — Defaults to false. When set to false, the error analysis verifies that detectors in the circuit are actually deterministic under noiseless execution of the circuit. Note that, unlike in Stim, logical observables are also allowed to be non-deterministic.
- `approximate_disjoint_errors` (`bool | float`) — Defaults to false. When set to false, composite error mechanisms with disjoint components (such as `PAULI_CHANNEL_1(0.1, 0.2, 0.0)`) can cause the error analysis to throw exceptions (because detector error models can only contain independent error mechanisms). When set to true, the probabilities of the disjoint cases are instead assumed to be independent probabilities. For example, a `PAULI_CHANNEL_1(0.1, 0.2, 0.0)` becomes equivalent to an `X_ERROR(0.1)` followed by a `Z_ERROR(0.2)`. This assumption is an approximation, but it is a good approximation for small probabilities. This argument can also be set to a probability between 0 and 1, setting a threshold below which the approximation is acceptable. Any error mechanisms that have a component probability above the threshold will cause an exception to be thrown.
- `ignore_decomposition_failures` (`bool`) — Defaults to False. When this is set to True, circuit errors that fail to decompose into graphlike detector error model errors no longer cause the conversion process to abort. Instead, the undecomposed error is inserted into the output. Whatever tool the detector error model is then given to is responsible for dealing with the undecomposed errors (e.g. a tool may choose to simply ignore them). Irrelevant unless decompose_errors=True.
- `block_decomposition_from_introducing_remnant_edges` (`bool`) — Defaults to False. Requires that both A B and C D be present elsewhere in the detector error model in order to decompose A B C D into A B ^ C D. Normally, only one of A B or C D needs to appear to allow this decomposition. Remnant edges can be a useful feature for ensuring decomposition succeeds, but they can also reduce the effective code distance by giving the decoder single edges that actually represent multiple errors in the circuit (resulting in the decoder making misinformed choices when decoding). Irrelevant unless decompose_errors=True.

### `get_graph`

```python
get_graph() -> Graph
```

Construct the circuit's quantum/classical ZX graph, with qubit ports.

Error parameters have the error index as their ID. Each detector and
observable is a classical XOR spider with its own classical output
boundary; their ports follow the qubit outputs (detectors, then
observables), so the graph's tensor is the circuit's channel together
with the detector and observable bits. ``Circuit.to_tensor`` returns the
channel alone.


### `get_sampling_graph`

```python
get_sampling_graph(sample_detectors: bool = False) -> Graph
```

Get a ZX graph that can be used to compute probabilities.

The graph is not doubled: qubit wires are quantum and measurement records
are classical spiders. It is constructed as follows:

1. Wire starts become ``|0⟩`` and wire ends are discarded.
2. Add outputs, which are classical boundaries:
(a) When sampling measurements (i.e. `sample_detectors` is False),
    add an output for each measurement. Detectors and observables are
    removed since they are ignored when sampling measurements.
(b) When sampling detectors and observables (i.e. `sample_detectors` is True),
    add an output for each detector, then for each observable.

Error parameters have the error index as their ID, so the graph's
``to_tensor`` needs a bit for every error index in its bindings (unbound
parameters raise); its tensor is then the joint distribution of the
outputs.

**Parameters:**

- `sample_detectors` (`bool`) — If True, sample detectors and observables instead of measurements.

**Returns:**

- `Graph` — A ZX graph for sampling.

### `to_tensor`

```python
to_tensor(bindings: Mapping[int, int] | None = None) -> np.ndarray
```

Return the circuit's doubled tensor (its channel, U ⊗ Ū for unitaries).

Axes follow zxparam's ``Graph.to_tensor``: outputs then inputs, by qubit,
each with a copy and a conjugate axis. Only qubits that some instruction
targets get axes, in increasing index order; qubits that no instruction
names are left out, so ``H 1`` gives a one-qubit tensor (add ``I q`` to
keep qubit ``q``). Error bits default to 0 (the noiseless circuit);
``bindings`` maps error indices to bits and raises ``ValueError`` for any
other key. Detector and observable annotations are left out. Needs
``zxparam[quimb]``.

### `sample`

```python
sample(shots: int, batch_size: int | None = None, prepend_observables: bool = False, append_observables: bool = False, separate_observables: bool = False, bit_packed: bool = False, use_detector_reference_sample: bool = False, use_observable_reference_sample: bool = False, postselection_mask: np.ndarray | None = None) -> np.ndarray | tuple[np.ndarray, np.ndarray]
```

Return detector samples from the circuit.

The circuit must define the detectors using DETECTOR instructions. Observables
defined by OBSERVABLE_INCLUDE instructions can also be included in the results
as honorary detectors.

**Parameters:**

- `shots` (`int`) — The number of times to sample every detector in the circuit.
- `batch_size` (`int | None`) — The number of samples to process at once. Defaults to None, which chooses it from the available memory. With ``strategy="active_statevector"`` it bounds the shots a thread holds and does not change the samples. With a stabilizer-rank strategy on a GPU, setting this explicitly can help fully utilize VRAM; it changes the samples of a seed.
- `separate_observables` (`bool`) — Defaults to False. When set to True, the return value is a (detection_events, observable_flips) tuple instead of a flat detection_events array.
- `prepend_observables` (`bool`) — Defaults to false. When set, observables are included with the detectors and are placed at the start of the results.
- `append_observables` (`bool`) — Defaults to false. When set, observables are included with the detectors and are placed at the end of the results.
- `bit_packed` (`bool`) — Defaults to false. When set, results are bit-packed. The packed rows may be a strided view of a wider array.
- `use_detector_reference_sample` (`bool`) — Defaults to False. When True, a noiseless reference sample is computed and XORed with detector outcomes so that results represent deviations from the noiseless baseline. This should only be used when detectors are deterministic. Otherwise, it can unpredictably change the results.
- `use_observable_reference_sample` (`bool`) — Defaults to False. When True, a noiseless reference sample is computed and XORed with observable outcomes so that results represent deviations from the noiseless baseline. This should only be used when observables are deterministic. Otherwise, it can unpredictably change the results.
- `postselection_mask` (`np.ndarray | None`) — Optional boolean array of length ``num_detectors``. When set, only the shots in which every masked detector reads 0 in the returned sample (after the reference sample is XOR-ed in, with ``use_detector_reference_sample``) are returned, so the result can have fewer than ``shots`` rows, and ``len(result) / shots`` is the acceptance rate. Without a mask, exactly ``shots`` rows are returned. A shot that a masked direct detector (an error bit or a constant) discards skips the components; with ``strategy="active_statevector"`` a masked component detector also stops a shot's simulation, while stabilizer-rank components are computed in full.

**Returns:**

- `np.ndarray | tuple[np.ndarray, np.ndarray]` — A boolean array of shape ``(rows, num_columns)``, or with
- `np.ndarray | tuple[np.ndarray, np.ndarray]` — ``bit_packed`` a uint8 array of shape ``(rows, ceil(num_columns / 8))``
- `np.ndarray | tuple[np.ndarray, np.ndarray]` — in little-endian bit order. ``rows`` is ``shots``, or fewer with a
- `np.ndarray | tuple[np.ndarray, np.ndarray]` — ``postselection_mask``. The columns are the detectors, with the
- `np.ndarray | tuple[np.ndarray, np.ndarray]` — observables prepended and/or appended if requested. With
- `np.ndarray | tuple[np.ndarray, np.ndarray]` — ``separate_observables``, a ``(detectors, observables)`` tuple of such
- `np.ndarray | tuple[np.ndarray, np.ndarray]` — arrays holding the same shots.

**Warns:**

- `UserWarning` — If a masked direct detector is a constant 1, without ``use_detector_reference_sample``, so that every shot is discarded.

**Raises:**

- `ValueError` — If ``separate_observables`` is combined with ``prepend_observables`` or ``append_observables``.

## `compile_program`

```python
compile_program(prepared: SamplingGraph, mode: DecompositionMode, strategy: SamplingStrategy) -> CompiledProgram
```

Compile a prepared graph into an executable sampling program.

The graph is split into connected components. A component whose single
output equals one error-basis bit or a constant takes the direct path. With
``strategy="active_statevector"`` every other component becomes an action tape for
the statevector executor. Otherwise its outputs are plugged (all prefixes
in ``sequential`` mode, none and all in ``joint`` mode), each plugged graph
is decomposed into stabilizer terms, and the terms are compiled into JAX
arrays.

**Parameters:**

- `prepared` (`SamplingGraph`) — The prepared graph from ``prepare_graph``.
- `mode` (`DecompositionMode`) — ``"sequential"`` for sampling, ``"joint"`` for probabilities.
- `strategy` (`SamplingStrategy`) — ``"active_statevector"``, or a stabilizer-rank decomposition strategy.

**Returns:**

- `CompiledProgram` — A CompiledProgram ready for sampling.

**Raises:**

- `ValueError` — If ``strategy="active_statevector"`` is combined with ``mode="joint"``.

## `evaluate`

```python
evaluate(circuit: CompiledScalarGraphs, param_vals: Array) -> Array
```

Evaluate compiled circuit with batched parameter values.

Each exact term family (``NodePhases``, ``PhaseTerms``, ``PiProducts``,
``PhasePairs``) computes its own contribution via ``.evaluate(param_vals)``.
This function multiplies those together with the per-graph
``ScalarPrefactor`` and merges ``power2`` into the exponent of the exact
product before converting to floating point, so the powers of two cannot
overflow or underflow separately. Any approximate floatfactor is multiplied
in afterwards. The floating-point ``FloatTerms`` family (angles that are not
multiples of π/4) is multiplied in only when the circuit has float terms.

**Parameters:**

- `circuit` (`CompiledScalarGraphs`) — Compiled circuit representation.
- `param_vals` (`Array`) — Bits of the compiled parameters (error-basis bits, then output bits), shape ``(batch_size, n_params)``.

**Returns:**

- `Array` — Complex array of shape ``(batch_size,)``: the summed scalars per sample.


## `kernel`

```python
kernel(function: Callable) -> Callable
```

Compile ``function`` serially and in parallel; ``run(work, *args)`` picks one.

``work`` estimates the call's cost in simple operations; calls below
``PARALLEL_WORK`` run serially, and so do calls on the worker threads of
``run_tasks`` and calls while numba has one thread. In the serial
compilation every ``numba.prange`` is a plain range, so both compute the
same result.


## `prepare_graph`

```python
prepare_graph(circuit: Circuit, sample_detectors: bool) -> SamplingGraph
```

Prepare a circuit for compilation.

1. Parse the Stim circuit into a quantum/classical ZX graph.
2. Close it into a sampling graph with classical outputs.
3. Reduce it with zxparam's ``full_reduce``.
4. Rewrite error bits as error-basis bits (Gaussian elimination).
5. Reset the scalar (normalization is computed separately).
